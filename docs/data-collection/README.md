# 住建数字化行业数据采集规范（v1）

## 目标与边界

首轮验证范围为“住建数字化 / 城市生命线”。一个城市作为一个行业验证单元，必须覆盖以下三类主体：**住建委（主管单位）+ 城管局（协同治理单位）+ 城投公司（建设/投资/运营主体）**。首轮先选择 1 个城市，三方合计采集 25–30 条可核验事件；验收阶段再复制到第二、第三个城市，扩展至 50–100 条。

每一项结论都必须能回溯到来源。原始资料、知识库资料和人工标注答案必须分开保存：原始资料说明“事实是什么”，黄金标注说明“系统应给出什么判断”。

## 交付目录

```text
<city>/
├── sources/                 # 下载的公开原文；文件名使用 source_id
├── source_manifest.jsonl    # 所有原始资料的索引和元数据
├── events.jsonl             # 待分析事件
├── organization_cards.jsonl # 三类单位、处室及职责/角色证据
├── capability_cards.jsonl   # 我方能力（脱敏后）
├── case_cards.jsonl         # 历史案例（脱敏后）
└── benchmark_labels.jsonl   # 人工黄金标注；不得由模型自动生成
```

本目录中的同名 `*_template.jsonl` 为可复制的单行 JSON 模板。JSONL 要求：UTF-8 编码、每行一个完整 JSON 对象、不添加注释或尾逗号。

## 通用字段与命名规则

| 字段 | 规范 |
| --- | --- |
| `*_id` | 稳定、不可复用的 ID，小写字母/数字/下划线/连字符，如 `hz_housing_001`。 |
| `source_id` | 原始来源唯一 ID，例如 `src_hz_2026_001`。同一文件只使用一个。 |
| `source_url` | 优先放官方可访问 URL；无 URL 时标注 `access_method` 和归档文件名。 |
| `published_at` | `YYYY-MM-DD`；未知则填 `null`，不得猜测。 |
| `effective_date` | 政策生效日期；不是发布日期。未知则 `null`。 |
| `evidence_ids` | 仅填写本批次真实存在、可打开核验的证据 ID。 |
| `confidence` | 人工判断可信度，0–1；不确定时降低分值并写入 `uncertainties`。 |
| `status` | `DRAFT`、`VERIFIED` 或 `REJECTED`。只有 `VERIFIED` 可进入 benchmark。 |

## 数据质量与合规规范

1. 优先级：政府官网/采购平台/正式文件 > 权威媒体 > 公开企业材料；不可验证的转载不作为关键证据。
2. 一条事件至少关联 1 条政策或项目证据，1 条单位/处室职责证据；若断言我方能力，再关联能力或案例证据。
3. 原文保留标题、发布日期、发布机构、URL、抓取日期和文件哈希；不要只摘录结论。
4. 不采集姓名、手机号、微信、身份证、非公开预算、账号密钥、合同全文等敏感数据。历史案例仅保留获得授权的公开/脱敏信息。
5. 不知道就填 `null` 或 `UNKNOWN`；禁止以常识补全单位职责、预算、牵头部门或项目阶段。
6. 每条 `VERIFIED` 标注须由业务评审人复核，并记录 `reviewed_by`（工号/姓名可替换为角色代号）和 `reviewed_at`。

## 推荐主题枚举

首批仅从下列主题中选取，并尽量保证三方主体均有明确角色证据：

```text
城市生命线、城市更新、CIM、智慧工地、住建数据治理、燃气安全、房屋安全
```

## 三方角色口径

| 主体 | 在首批数据中的默认角色 | 需要重点收集的证据 |
| --- | --- | --- |
| 住建委 | 政策统筹、行业主管、建设任务牵头或协同 | 机构职责、实施方案、项目立项、专项规划 |
| 城管局 | 运行监管、城市治理协同、执法/设施运行相关职责 | 机构职责、运行监管要求、联动处置机制、采购公告 |
| 城投公司 | 投融资、建设实施、平台运营或项目业主（以当地公开资料为准） | 公司公开职责、项目主体公告、招采公告、运营公告 |

不得将以上角色视为事实默认值：每个城市、每个项目均须以职责文件、公告或项目材料为证据确认；无直接证据时标注 `UNKNOWN`。

## 验收前检查

- [ ] 已确定 1 个城市，住建委、城管局、城投公司三方的基本信息完整。
- [ ] 三方合计 25–30 条事件；建议住建委 8–10 条、城管局 8–10 条、城投公司 5–10 条，至少 80% 来自近 24 个月。
- [ ] 每条 `VERIFIED` 事件有来源链接、原文归档和至少 2 类证据。
- [ ] 每条黄金标注都包含主题、需求、三方单位候选及其项目角色、处室/部门 Top 3 和证据 ID。
- [ ] 能力卡与案例卡均确认可使用且已脱敏。
- [ ] 不存在重复 URL、失效关键链接、孤立 `source_id` 或不存在的 `evidence_id`。
- [ ] 业务评审人完成复核并记录不确定项。

## 与当前系统的对接

将已核验的来源转为 `KnowledgeDocumentInput` 后，可通过 `POST /api/v1/knowledge/documents` 写入 PostgreSQL 知识库。黄金标注需要再汇总为 `evaluation/benchmark_housing_v1.json` 的案例格式；不要直接将原始事件当作黄金答案。
